Design system / dark-first

Clarity is the interface.

LinearStories pairs an editorial human voice with the precision of developer tooling. The system should feel calm, exact, and quietly luminous—never ornamental at the expense of understanding.

Goal Intent before interface

Lead with why the work matters, then reveal the mechanics.

Work Hierarchy is structure

Use rails, nesting, and spacing to make relationships obvious.

Proof State must be observable

Every action, status, and criterion gets a legible signal.

08 / Components

Usage principles

Do
  • Lead each view with one clear outcome.
  • Use spacing and alignment before adding containers.
  • Reserve the gradient for action and structural emphasis.
  • Write labels that describe the result of an action.
Avoid
  • Multiple equally prominent calls to action.
  • Serif type for dense operational content.
  • Decorative glows without information value.
  • Colour-only status or vague error messages.
12 / Standards

Accessibility

Clarity includes everyone. Components must remain understandable with a keyboard, screen reader, reduced motion, zoom, or without colour perception.

01 / Contrast

Text stays legible

Use primary text for headings, secondary for body copy, and muted text only for non-essential metadata. Never place muted text on raised surfaces for required information.

02 / Input

Keyboard is first-class

All controls need a visible focus ring, logical order, accessible name, and a hit target of roughly 40px or larger for primary interactions.

03 / Motion

Movement has purpose

Use the 150–220ms range for feedback and the 700–900ms range only for one orchestrated entrance. Honour prefers-reduced-motion.
